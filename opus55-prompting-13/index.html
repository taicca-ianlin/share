13 個該改的習慣

新模型更會自己想、自己做長任務。很多舊時代的寫法現在反而讓它變慢、多燒 token。這頁把 Gary Chen 的影片整理成 13 張卡，每張附「現在就能做的一件事」。

一、Effort：想多久

effort 是「回答前想多久」的旋鈕。越高越慢、越貴。

0100:30

預設用 medium 就好

上一代預設 high，這代改成 medium。但同一級這代想得更多：官方測試 5.5 的 medium 已追平甚至超過上一代的 high。

做：以前手動拉到 xhigh／max 的，先調回 medium。

0201:14

用你自己的工作去測

挑一件每週都做的事，用 low、medium、high 各跑一次，再請 Claude 比較三份成品。low 夠用就用 low。xhigh／max 沒實測出明顯差異就不值得開。

做：挑一件例行工作跑三個等級比一次。

0302:00

中途換 effort 不再清快取

快取（cache）＝已讀過的對話先存著，下次直接用，又快又省。以前中途換 effort 會讓它作廢；5.5 不會了。簡單追問降 low，難題再拉高。

例外走 Amazon Bedrock、Google Cloud 串接時暫不適用。

二、提示詞怎麼寫

把舊模型時代的「補丁」拿掉，直接講你要什麼。

0402:46

一次講完整，定義「做完長什麼樣」

官方範例有三塊：任務本身、終點狀態、什麼情況才准停下來問你。三樣講清楚，就放手讓它跑。

做：交辦時固定寫「任務／終點／暫停條件」三行。

0503:37

刪掉「請仔細思考」

它本來就會先想，也會自己判斷要想多久。官方測試拿掉這句，回覆變快、品質沒明顯掉。想快就寫「請直接回答」；想調深度就動 effort。

做：翻 CLAUDE.md 與常用 prompt，刪掉 think step by step 類字眼。

0604:27

不要叫它寫出推理過程

5.5 多了安全檢查，要求重現內部推理的請求可能被拒。需要理由就直接問理由，例如「用三句話說你為什麼選這個做法」。

做：把「寫出你的思考過程」改成「說明理由」。

0705:05

做設計：列出你不要的

沒給方向，它會回到慣用的預設風格；只說「不要像 AI 做的」沒用。要直接點名：例如不要米白底、不要斜體標題、不要 01/02/03 編號區塊、不要藥丸按鈕。不喜歡新結果就再加進黑名單。

做：維護一份設計黑名單，或直接給設計規範檔。

三、長任務與分身

5.5 最大的進步是多步驟長工作。但要管好它「停」與「交差」的時機。

0805:51

在 CLAUDE.md 規定何時才問你

它愛犯三種毛病：寫完「下一步要做什麼」就停住、客氣問要不要繼續、列一堆其實不影響進度的選項。官方建議寫明：不需要我的步驟直接做；進度和下一步放同一則；只有缺我的指示，或要做刪資料、強制推送、改專案外檔案這類破壞性動作前才停。

注意放手讓它衝，破壞性指令的權限確認要保持開著。

0906:45

叫它維護一份 checklist 檔案

它停下來講的話只是「進度回報」，不代表做完。對話太長會被壓縮成摘要，清單只在聊天裡就可能消失；寫在檔案裡就不會。

做：prompt 結尾加「建立 checklist 檔，做完打勾、有新工作就加」。

1007:36

超大任務拆給 subagent

subagent＝主 Claude 派出去的分身，各做一小塊再回報。適合大型稽核、系統搬遷、大範圍審查。關鍵一句不能省：分身回報時，先檢查證據才接受，最後整理成「有沒有中＋證據」的表。

做：交辦大任務時寫明「回報要附證據，主 Claude 驗過才收」。

1108:14

給時間預算，或說「時間很重要」

5.5 對時間很敏感。給它預算（例如 20 分鐘），它會自己調步調，常常提早完成；預算要給得比期望寬一點。估不出來就寫「時間很重要，能省就省」。這和調低 effort 不同：它會讓更多分身平行開工。

做：多 agent 任務的交辦加一行時間預算。

四、兩個實用更新

不算提示技巧，但對從其他工具回來的人很方便。

1209:07

Claude Code 讀得懂 AGENTS.md

AGENTS.md 是 Codex 等工具用的專案指示檔。資料夾裡沒有 CLAUDE.md 時，新版 Claude Code 會改讀 AGENTS.md；有 CLAUDE.md 就只讀 CLAUDE.md。

做：同時用多種工具的人，可考慮只維護一份 AGENTS.md。

1309:54

可以存起來的用量重置券

影片說：Opus 5.5 推出後，訂閱用戶應收到一次免費重置，可自己決定何時發動，到 10 月 23 日作廢。位置在 Settings → Usage。

期限10/23 前去確認並用掉（以你帳號實際畫面為準）。

總結：只做三件事

模型越強，越不用手把手教它怎麼做；你該花力氣的，是把「到底要什麼」定義清楚。

講清楚終點

任務、做完的樣子、何時才准停。

刪掉舊補丁

「仔細思考」「寫出推理」這類為舊模型寫的指令。

規定何時停

其餘過程放手，破壞性動作前才問。
